---
name: Marketplace foundation
description: Product direction and persistence boundary for the first Mahathi shopping experience.
---

Mahathi's initial commerce UX is intentionally static and client-side: local catalog data powers browsing, while wishlist and cart counts use browser storage until authentication, server persistence, and checkout are explicitly added.

**Why:** The user wants a polished marketplace experience first, while deliberately deferring authentication, database work, payments, and admin functionality.

**How to apply:** Preserve the shopping conventions and original Mahathi palette when extending the app, but do not introduce account or payment assumptions into the current static foundation.
